Architectural pattern: Feature-Sliced Design

To prevent monolithic coupling and technical debt within a multi-vertical ecosystem, the codebase enforces a Feature-Sliced Design (FSD) paradigm. This strictly isolates business domains and enforces unidirectional dependency graphing.

src/
├─ shared/         Core infrastructure primitives (domain-agnostic)
│  ├─ api/         Relational schema definitions, stateless DB clients
│  ├─ ui/          Atomic design components
│  └─ lib/         Cryptographic helpers, deterministic date formatters, regex sanitizers
├─ entities/       Domain object abstractions
│  ├─ asset/            Standardized inventory presentation components
│  └─ user-profile/     Federated identity badges and reputation metrics
├─ features/       Isolated business logic and workflows; contract exposed via index.ts
│  ├─ transactional-custody-gateway/   Cryptographic title transfer, multi-party settlement logic
│  ├─ predictive-asset-simulation/     External API polling to render dynamic optimizations
│  ├─ automated-diagnostic-triage/     Cognitive visual processing routes operational anomalies
│  └─ provenance-validation-matrix/    Historical archival data cross-referenced with regulatory databases
└─ app/            Route orchestration layer: stateless layout composers
   ├─ (discovery)/page.tsx                         Primary top-of-funnel asset aggregation feed
   ├─ (settlement)/checkout/page.tsx               Secure enclave for final financial execution
   └─ (commercial-dashboard)/dashboard/page.tsx    B2B portal for dynamic quota management

Medical education platform, iOS, Android and web

StatusDesign, Architecting and Prototyping

Gamified clinical learning for medical students.

Turns lecture packs and past papers into AI-generated clinical cases, multiplayer battles and spaced-repetition review, mapped automatically to each student's degree and year.

Core technology stack
Frontend frameworkFlutter 3.x (Dart). Single codebase compiled natively for iOS, Android, and Web platforms.
Backend as a serviceAppwrite (v1.5+). Open-source BaaS managing user authentication, document databases, storage buckets, and real-time WebSockets.
Primary databaseMariaDB (Appwrite-managed). Relational-style collections for user profiles, RPG experience points (XP), learning blueprints, and battle item inventory.
Vector databaseQdrant. Self-hosted in a Docker sidecar container running on the same server alongside Appwrite to store AI embeddings and perform vector search for RAG verification and question deduplication without third-party subscription costs.
AI inference modelsOpenAI GPT-4o-mini and Anthropic Claude 3 Haiku. Accessed strictly server-side via Appwrite Functions for rapid, cost-effective clinical case generation and interactive simulations.
Serverless functions runtimeNode.js / TypeScript / Dart. Appwrite Functions handling server-side game logic, PII scrubbing, academic verification, and AI API proxying.
Hosting and infrastructureSelf-hosted Docker Compose on a Linux Virtual Private Server (VPS) such as Hetzner, DigitalOcean, or Linode (4GB–8GB RAM). Web builds are deployed on Cloudflare Pages or Vercel.
Architectural and engineering patterns
Architectural and engineering patterns
Sidecar container patternRunning Qdrant alongside Appwrite on a single VPS, keeping vector retrieval local and high-speed while eliminating expensive third-party cloud database fees.
Event-driven serverless architectureUtilizing Appwrite Functions triggered by authentication events, file storage uploads, or HTTP requests.
Realtime WebSocket synchronizationUtilizing Appwrite Realtime WebSockets to broadcast document state changes across subscribed clients in room channels, enabling low-latency multiplayer game sync.
Document-level security (DLS)Enforcing granular Appwrite access control lists across collections so users hold exclusive write access to their own progression data.
RAG and vector deduplicationUploaded PDF lecture packs and past papers are extracted, chunked, and checked against local Qdrant vector indices using cosine similarity search.
Automated PII redaction pipelineA fast, Regex-based serverless pre-processing function that automatically scrubs Protected Health Information (PHI) and patient identifiers.
Server-side API key proxyingStoring all OpenAI and Anthropic API keys strictly as serverless environment variables.
Server-validated game stateBattle room actions, speed critical damage multipliers, and item effects are calculated strictly server-side.
Spaced repetition engine (SM-2 variant)A custom rules engine that calculates review intervals, error counts, and mastery levels to populate the Mistake Notebook.
Automated curriculum mappingParsing institutional email domains upon registration to automatically route students to the appropriate degree and academic year syllabus.

SyncBite

B2B micro-SaaS, hospitality middleware and EPOS bridge

StatusDesign, Master Requirements, Architecting

Cascade inventory sync and middleware for cafes and dessert parlours.

A cloud-based API bridge connecting EPOS systems such as Square directly to Uber Eats, Just Eat and Deliveroo, preventing stockouts and cancelled-order penalties.

Core technology stack
Frontend frameworkNext.js hosted on Vercel. Orchestrates multi-tenant routing, distinguishing between global administrative consoles, tenant-specific operational dashboards, and dynamic consumer-facing digital storefronts.
Backend middlewareNode.js hosted on Render. Functions as the primary API gateway, processing third-party integrations, hardware actuation commands, and high-volume transactional logic.
Database infrastructureTurso (libSQL). Employs a scalable database-per-tenant architecture, ensuring strict data isolation and optimized edge latency for each enterprise client.
Object storageCloudflare R2. Manages all tenant-specific digital assets and media files, optimized for high-availability content delivery networks.
Identity and access managementAuth.js. Facilitates secure, role-based access control and multi-tenant authentication protocols for administrative and operational personnel.
Transactional communicationsResend. Manages automated programmatic dispatch for system alerts, password resets, and digital consumer receipts.
Integrations and API architecture
Integrations and API architecture
Multi-party payment gatewayStripe Connect. Automates online transaction processing, dynamically calculating platform commissions and programmatically routing the remaining capital to the respective tenant's connected financial account.
Point-of-sale hardware APISquare Terminal API. Executes server-to-server communications to push payment payloads directly to physical, on-site transaction terminals.
External marketplace synchronizationThird-party delivery APIs. Automates digital menu ingestion and real-time inventory adjustments across external delivery aggregator platforms.
Automated ledger accountingFreeAgent API. Programmatically pushes itemized daily sales data, automatically calculating regional tax splits and formatting the output for corporate accounting reconciliation.
Architectural design patterns
Architectural design patterns
Database-per-tenant isolationRather than co-locating client data in a monolithic database, the infrastructure automatically provisions a dedicated, siloed database instance for each tenant, ensuring zero cross-tenant data leakage and strict enterprise compliance.
Event-driven webhook architectureThe backend middleware utilizes event listeners to monitor database threshold triggers (e.g., inventory depletion) and dispatches real-time API requests to external delivery networks to update availability dynamically.
Atomic database transactionsAll inventory modifications, whether originating from digital storefronts, on-site terminals, or external marketplaces, are processed as atomic transactions to guarantee data integrity and prevent race conditions.
Automated batch processingScheduled cron jobs execute during off-peak hours to aggregate daily transactional data, separate tax categories, and generate compliant financial payloads for external accounting platforms.
Local network hardware bridgingTo actuate localized physical hardware (e.g., electronic cash receptacles), the primary application transmits standardized ESC/POS commands over the local area network to peripheral devices, triggering localized electrical actuation via bridging components.
